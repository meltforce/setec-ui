# setec-ui — a native macOS client for the homelab setec server

A SwiftUI app that manages secrets in [setec](https://github.com/tailscale/setec)
over the tailnet: list, reveal, copy, publish a version, activate, delete, copy
or move. A client only: it stores no secret, holds no policy, runs no server.

## Gotchas

Product:

- **Never persist a secret value**: no cache, `UserDefaults`, log line or crash
  report. Reveal auto-hides after 20 s; a copied value is cleared on a timer
  and marked `org.nspasteboard.ConcealedType`. Values are fetched only on
  Reveal, Copy and Start from current.
- **Development runs against the production store.** A `put`, `activate` or
  `delete` from a Debug build changes a real secret; use a throwaway prefix.
- **`make run` inherits the shell's `SETEC_SERVER`, which wins over the
  Settings field**; a Dock launch has none. Test another server with
  `env -u SETEC_SERVER open -n ".build/Build/Products/Debug/Setec UI.app"`.
  The app carries no built-in server.
- Namespaces are not objects (names are flat strings split on `/`); rollback
  is `activate`; `confirm-token` is not surfaced. Do not add affordances for
  any of them.
- **A write is confirmed by re-reading, never by the status code**
  (`SecretStore.Unconfirmed`).
- **The access matrix is display-only**, and its grants come from the Tailscale
  control API through a read-only OAuth client held in two setec entries
  (homelab `SECRETS.md` § *Tailscale control API*). An auth key answers 401. It
  keeps "setec unreachable" apart from "credential unreadable".
- `design/` is a specification, not a source tree; it is light-mode only and
  the dark palette in `App/Design/Palette.swift` is this repo's own.

SwiftUI:

- An `.accessibilityIdentifier` on a container replaces every child's; put
  identifiers on leaves.
- No tooltip works here (`.help`, `NSView.toolTip`); explanations go inline.
- `.buttonBorderShape(.circle)` needs a label with an explicit square frame; an
  icon-only menu button is `App/Components/IconMenuButton.swift`.
- A synthesized mouse move does not reach `.onHover`; assert hover in a UI
  test (`XCUIElement.hover()`).
- A `confirmationDialog` cannot be driven by the agent; a destructive
  confirmation is a sheet (`App/Sheets/DeleteVersionSheet.swift`).

Release:

- **A release is a tag on Forgejo; the DMG is built on GitHub**
  (`.github/workflows/release.yml`), the mirror. Nothing may originate on
  GitHub. `README.md` § *Releases* has the tag form.
- `/bin/bash` on the GitHub runner is 3.2; `make check` runs
  `tools/check-workflow.sh` over every `run:` block.
- Staple the app first, then build and submit the image from the stapled
  bundle. `scripts/package.sh` passes `CODE_SIGN_INJECT_BASE_ENTITLEMENTS=NO`
  and checks for `get-task-allow`.
- The version is `YYYY.MM.DD`, three components at most; a second release on
  one day raises the build number.
- Without `~/bin/axdump`/`winid` and the skills (`make install-tools
  install-skills` in `mac-app-template`) the app still builds; `make run`
  then reports "no window after 15 s".
- Fleet conventions: homelab `configuration/macs/README.md` § *Self-built Mac
  apps*, `SECRETS.md` § *Apple code signing*.

## Mac app

A native SwiftUI app scaffolded from `mac-app-template`. `project.yml` is the
project; `*.xcodeproj` is generated by `make project` and gitignored. The
`Makefile` lists the targets; the ones a task uses are `make run`, `make check`
(lint, build, unit tests: the gate after a change), `make verify` (`check` plus
UI tests: before `make install`), `make screenshot`, `make inspect`,
`make click ID=…`, `make eval CMD=state`, `make logs`, `make stop`.

Skills: `mac-app-run` before building or launching, `mac-ui-patterns` before
writing a view, `mac-app-verify` before reporting a task done, `mac-app-icon`
for the icon.

- A green build proves valid code, not a finished feature. A change to app code
  ends with `make check`, `make run` and evidence (screenshot, `state` dump,
  click); say which requested behaviour was not exercised.
- Inspection budget: five `inspect`/`click`/`eval`/`screenshot` calls per
  build, three build-and-inspect cycles per task. Past that, state what remains
  unverified.
- Quit with `make stop`, never `pkill`: a forced quit leaves window restoration
  state without windows, and the next launch shows none.
- Every control the agent or a test must find carries an
  `.accessibilityIdentifier` (`feature.element`) and is a `Button`;
  `.onTapGesture` does not answer accessibility activation.
- Register state and actions with `DebugServer` in `AppDelegate` for anything
  to verify without a screenshot (DEBUG builds only).
- A menu shortcut that does nothing is a missing `@FocusedValue` or a first
  responder consuming the key, not a wrong `keyboardShortcut`.
- TCC grants are keyed to team ID plus bundle ID, both fixed in `project.yml`.
- UI strings: English is the base language in the string catalog; German lives
  in the localization. `Text("… \(anInt)")` groups digits by locale; use
  `Text(verbatim:)` for ids, ports and build numbers.
- A `URLProtocol` stub must not touch a `@MainActor` test class (symptom:
  `Executed 0 tests`); record into a separate lock-protected object.
- Every view carries a `#Preview`. A `NavigationSplitView` with `.inspector`
  aborts the preview host; preview one column at a time.

Xcode's MCP server (`.mcp.json`, `xcrun mcpbridge`; once per machine
`sudo xcrun mcp-server enable`):

- Start with `XcodeOpenWorkspace`; its `workspaceIdentifier` goes stale when
  xcodegen regenerates the project (`Unknown workspace identifier`).
- Tools take project paths (`<Module>/App/Shell/RootView.swift`), not
  filesystem paths; `XcodeGlob` resolves a name.
- `BuildProject`/`RunProject` build into Xcode's DerivedData, not `.build/`;
  `make run`, `screenshot` and `eval` need the `make` build.
- Write build settings, entitlements and `Info.plist` keys in `project.yml`;
  the MCP write tools edit the generated project and are overwritten.
- `RenderPreview` variant groups: `Color Scheme`, `Contrast`, `Control Borders`.

## Git

`main` is the only long-lived branch: commit and push to `main` yourself once a
change is complete and verified, no PR. This overrides the harness default of
branching first. Stage paths explicitly, never `git add -A` — parallel sessions
share this checkout.

## Documents

Do not write documentation that restates the code. Reasoning goes into the
commit message, or into a comment next to the code when a later reader would
otherwise undo the change. Everything written into the repo is English.
`archive/` holds the former decision log and postmortems, frozen.
